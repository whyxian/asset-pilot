## 🔴 严重问题

### 1. `calculate_portfolio_overview` 全程 float — 与 Decimal 路径精度分歧

**文件**：`backend/app/core/formulas.py:248-286`

**问题**：`calculate_portfolio_overview` 内部全部用 float 算术（`total_shares * current_price`），而 `calculate_modified_dietz` 和 `calculate_xirr` 内部已改为 Decimal。三个公式算同一个财务量（收益金额），但精度路径完全不同：

- 总盈亏卡片：`calculate_portfolio_overview` → `total_value: float` → `Decimal(str(float))`（有精度损失）
- 历史累计收益：`calculate_modified_dietz` → `net_profit: Decimal`（无精度损失）

**后果**：两个卡片算出的「收益金额」差 ¥21（Decimal→float→str→Decimal 的累积误差），用户困惑。

**根本原因**：`overview_service.py:55-60` 把 Decimal 的持仓数据全部转成 float 传给公式，公式内部用 float 算完再 `Decimal(str(result))` 回来，中间的精度损失无可挽回。

**修复方向**：`calculate_portfolio_overview` 改为接收 Decimal 输入 + 内部 Decimal 算术（与 Modified Dietz / XIRR 统一）。overview_service 传 Decimal 而非 `float()` 转换。

> ✅ **部分修复**：Modified Dietz 已改为 Decimal（`8da900a`）。portfolio 公式尚未修复。

---

### 2. `calculate_remaining_position_roi` 全程 float — 与 Decimal 持仓数据精度分歧

**文件**：`backend/app/core/formulas.py:28-63`

**问题**：`asset_holding_service.py:328-331` 和 `snapshot_service.py:76-79` 调用时把 Decimal 持仓字段转成 float：

```python
current_price=float(current_price),
broker_cost_price=float(h.cost_price),
initial_buy_price=float(h.first_buy_price),
total_shares=float(h.quantity),
```

公式内部所有数学是 float，`rate_of_return: float` 返回值。同时 `pnl`（持仓盈亏金额）在 service 里用 Decimal 计算（`market_value - total_invested`），两条路径精度不同。

**后果**：`pnl`（Decimal 精度）和 `rate_of_return` 背后隐含的 `net_profit`（float 精度）对同一笔持仓可能微量不一致。当前只影响百分比显示（精度足够），但未来 `net_profit` 被消费时会暴露精度差异。

**修复方向**：`calculate_remaining_position_roi` 改为 Decimal 输入+内部 Decimal 算术，与 portfolio/Dietz/XIRR 三个公式统一。

### 3. `overview_service:97` — Decimal→float→str→Decimal 三重转换

**文件**：`backend/app/services/overview_service.py:95-97`

```python
amt = float(t.amount) * (-1 if t.type == "sell" else 1)
amt_usd = float(convert_with_rates(Decimal(str(amt)), ccy, "USD", rates))
```

`t.amount` 是 Decimal（来自 ORM）→ `float()` 转一次 → `Decimal(str(float))` 转回来 → `convert_with_rates`（Decimal）→ `float()` 再转一次。这是本次 ¥21 差异的直接来源。

**后果**：Modified Dietz 的 `net_profit` 虽然内部全程 Decimal，但输入端已经因 float 转换损失精度，最终结果仍与 `total_pnl_usd`（Decimal 源）不一致。

**修复方向**：`trade_flows` 直接传 Decimal，不在 overview_service 里做 `float()` 转换。`convert_with_rates` 返回 Decimal，结果直接赋给 `flow["amount"]`，改为 `Decimal(str(t.amount))` 或 `Decimal(t.amount)` 替代 `float()`。后续由 Dietz/XIRR 公式内部处理类型。

## 🟡 中等问题

### 4. `overview_service:55` — `float(entry[0].price)` 转换丢失 Decimal 精度

**文件**：`backend/app/services/overview_service.py:55`

```python
current_price = float(entry[0].price) if entry else 0.0
```

`entry[0].price` 是 Decimal（DB 出来的），转 float 丢精度。该值既传给 `calculate_portfolio_overview`（float 路径），又用于 `convert_with_rates(h.quantity * Decimal(str(current_price)), ...)`（Decimal 路径）。`Decimal(str(float))` 的 round-trip 对大部分股票价格精度足够（2 位小数），但对加密货币（BTC 6 位小数）可能有微小误差。

**修复方向**：`current_price` 保持 Decimal，不转 float。传给 portfolio 公式时也直接传 Decimal（公式改为 Decimal 输入后自然兼容）。

### 5. `snapshot_service:76-79` 和 `112-115` — 与 `#2` 相同的 float 转换

**文件**：`backend/app/services/snapshot_service.py:76-79` 和 `:112-115`

```python
current_price=float(current_price),
broker_cost_price=float(h.cost_price),
initial_buy_price=float(h.first_buy_price),
total_shares=float(h.quantity),
```

快照计算时同样把 Decimal 转成 float 传给公式。`return_pct`（快照盈亏率）结果是 float，存入快照表——但快照本身是历史数据，精度损失永久固化。

**修复方向**：同 `#2`，公式统一 Decimal 后此处自然解决。

## 根本原则

**金额类字段（Decimal）不应转成 float 传给公式，公式应直接接收 Decimal**。`float()` 转换永远有精度损失，`Decimal(str(float))` 不是无损 round-trip（对非二进制可表示的小数如 0.1、0.2、0.01 等都会累积误差）。本次 ¥21 差异就是这条原则被违反的直接后果。
