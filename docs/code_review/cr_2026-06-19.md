## 🟡 中等问题

### 1. `services/overview_service.py:167` — quote_map 用单 ticker key，跨组 ticker 冲突会覆盖

```python
async def _fetch_quote_map(self, groups, force_refresh):
    ...
    for t in done:
        for q in t.result():
            quote_map[q.ticker] = q   # ❌ 单 ticker key
    return quote_map
```

`get_overview` 按 `(asset_class, market)` 分组并发拉取，但 `quote_map` 用裸 `q.ticker` 作 key。取用处（`overview_service.py:54,78`）也是 `quote_map.get(h.ticker)`。

对照 `asset_holding_service.py:136` 刻意用了三元组 key：

```python
quote_map[(ac, market, q.ticker)] = q   # ✅ 三元组防冲突
```

注释还专门写了「行情按 (asset_class, market, ticker) 三元组定位，避免不同品种 ticker 冲突」。A 股代码 `000001` 既是平安银行（STOCK）也可能命中某基金（FUND），同一 ticker 在 STOCK+CN 和 FUND+CN 两组都会出现时，后完成的组会覆盖前者，导致其中一个品种用错行情价算市值。

**建议**：overview 同样用三元组 key，取用处改 `quote_map.get((h.asset_class, h.market, h.ticker))`，与 holding service 保持一致。

> ✅ **已修复：** `_fetch_quote_map` 返回类型改 `dict[tuple[str,str,str], object]`，填充改 `quote_map[(ac, market, q.ticker)]`，两处取值改三元组 key。新增 `test_fetch_quote_map_avoids_cross_group_ticker_collision` 验证 000001 同时作为 A 股和基金时两条行情互不覆盖。

## 🟢 轻微问题

### 3. `services/asset_quote_service.py:24,54` — force_refresh 参数对 stock/crypto 完全无意义，签名冗余

```python
async def fetch_stock_quotes(self, market, codes, force_refresh: bool = False):
    """...
    force_refresh: 股票无缓存，每次都走网络，此参数仅为签名一致（忽略）
    """
    quotes = await self._stock_repo.fetch_realtime_quote(codes, market=market)  # force_refresh 从未使用
```

`fetch_stock_quotes` / `fetch_crypto_quotes` 加了 `force_refresh` 参数但函数体完全不用。虽然 docstring 标注了「仅为签名一致」，但这是个误导性设计——调用方可能误以为传 `force_refresh=True` 对股票有某种效果。真正需要 force 行为的只有 `fetch_fund_quotes`。

**建议**：stock/crypto 不加该参数；`fetch_quotes_by_asset_class` 路由处只在 FUND 分支传 `force_refresh`，STOCK/CRYPTO 分支不传。减少误导面。

### 4. `utils/exchange_rate.py:42` — `or` 短路在 rates 为空 dict 时误判

```python
rates = payload.get("rates") or payload.get("datas")
```

`payload.get("rates")` 若返回空 dict `{}`（理论上可能，如数据源异常返回空表），`{}` 是 falsy，会错误地继续取 `datas` 字段。虽然概率极低，但兜底逻辑应保守。

**建议**：用显式判断 `rates = payload.get("rates"); if not rates: rates = payload.get("datas")`，或 `payload.get("rates") if payload.get("rates") is not None else payload.get("datas")`。

> ✅ **已修复：** 改为 `rates = payload.get("rates"); if rates is None: rates = payload.get("datas")`，空 dict 不再误回退。

### 5. `services/overview_service.py:154-156` — pending 任务 cancel 后未 await，可能产生未消费的取消异常

```python
for t in pending:
    t.cancel()
if pending:
    logger.warning(...)
```

`asyncio.wait` 超时后 pending 任务被 cancel，但没有 `await asyncio.gather(*pending, return_exceptions=True)` 收尾。被取消的协程内部的 `CancelledError` 若未被消费，事件循环关闭时可能打印 "Task was destroyed but it is pending!" 警告，且协程内的 httpx 连接清理时机不确定。

**建议**：cancel 后 `await asyncio.gather(*pending, return_exceptions=True)` 确保取消异常被消费、连接清理完成。

> ✅ **已修复：** 超时分支 cancel 后加 `await asyncio.gather(*pending, return_exceptions=True)`；外层 except 分支同样补 `await asyncio.gather(*tasks, return_exceptions=True)` 收尾。

### 6. `utils/exchange_rate.py:7` — 模块 docstring 与实际不符

```python
- 两级兜底：内存 L1（1h TTL，新鲜）+ 磁盘 L2（持久，进程重启不丢）
  网络失败 → 用内存旧值（哪怕过期）→ 用磁盘旧值 → None
```

文档说「两级兜底」，实际已是四级（内存新鲜 → 内存过期 → 运行时缓存 → 种子文件）。`fetch_rates` 的 docstring 写对了（「两级兜底」也不准，但至少列了完整链路），模块顶部这条没更新。

**建议**：模块 docstring 改为「四级兜底」并更新链路描述，与 architecture.md §5.7 一致。

> ✅ **已修复：** 模块 docstring 改为「四级兜底：内存新鲜值 → 内存过期旧值 → 运行时磁盘缓存 → 种子文件」。

### 7. `services/overview_service.py:38` — `rates = await fetch_rates() or {}` 静默吞掉汇率不可用

```python
rates = await fetch_rates() or {}
```

四级兜底全部失效时 `fetch_rates()` 返回 None，`or {}` 变成空 dict。随后 `convert_with_rates` 走「汇率缺失，返回原值」分支——CNY 市值和 USD 市值会被当同币种直接相加，总市值静默算错，只在 `convert_with_rates` 内部 warn 一次。

虽然加了四级兜底后这个场景概率极低（要全新环境 + 无种子 + 断网才会发生，而种子已入库），但「静默算错」仍比「报错」危险。

**建议**：`rates` 为空时记一条显眼 error 日志（"汇率全部不可用，概览数值将不准确"），便于运维发现。或者考虑在该场景下抛 BusinessError 让前端显示错误态，而不是返回错误数据。

> ✅ **已修复（更彻底的方案）：** 把种子文件汇率硬编码为 `_HARDCODED_RATES` 常量嵌入 exchange_rate.py，兜底链升级为五级（内存新鲜 → 内存过期 → 运行时缓存 → 种子文件 → 硬编码常量）。`fetch_rates` 返回类型改为 `dict`（永不 None），overview 处 `rates = await fetch_rates() or {}` 简化为 `rates = await fetch_rates()`。即使种子文件被删 + 断网，硬编码常量也能兜住，概览不再静默算错。

## 🔵 后续改进（审查后新增，非原问题）

### A. 汇率日期 + 新鲜度透传到前端 ✅ 已实现

多级兜底意味着系统可能**静默地用旧汇率**算概览（如断网走硬编码 2026-06-18 汇率），用户看到的「总市值」可能按几天前汇率换算却完全不知情。本次把汇率日期与新鲜度一路透传到前端展示。

**数据通路**：`fetch_rates() → RatesSnapshot{rates, source_date, is_stale}` → `OverviewStats.rate_source_date / rate_stale` → `/api/v1/overview` → 概览页脚。

- `is_stale=False`：网络成功 / TTL 内缓存命中（数据源每小时更新，1h 内可接受）
- `is_stale=True`：网络失败走了任何兜底（内存过期 / 磁盘 / 种子 / 硬编码）

前端页脚动态展示：fresh 时正常色「更新于 2026-06-19」；stale 时橙色警告「⚠ 汇率非最新（来自 2026-06-18），网络异常时使用历史汇率兜底」。

> 仅概览页涉及汇率换算（持仓页每行显示原币种价格，不换算），故只概览页脚需要展示。
